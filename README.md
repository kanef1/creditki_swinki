# Кредитный модуль для бизнеса

Одностраничный модуль для встраивания в банковский сайт. Четыре раздела: **Продукт → Условия → Заявка → Результат**. Самостоятельный портал, боковое меню и экран входа удалены по уточнённому заданию пользователя.

React 18 / TypeScript / Vite / Tailwind / Radix UI, Django 5.2 / DRF / PostgreSQL 16. Финансовая логика работает на сервере, заявки сохраняются в PostgreSQL. Все компании, условия и проверки синтетические; реальных банковских интеграций и выдачи денег нет.

## Запуск

Нужны Docker Desktop с Linux engine и Compose v2. Если pipe docker_engine не найден, сначала запустите Docker Desktop (`docker desktop start` при наличии Desktop CLI).

```sh
docker compose up --build -d --wait
```

- Модуль без экрана входа: http://127.0.0.1:8080/
- Swagger: http://127.0.0.1:8080/api/docs/
- OpenAPI: http://127.0.0.1:8080/api/schema/
- Backend + БД: http://127.0.0.1:8080/health/

Миграции и синтетические продукты создаются автоматически. После обновления используйте Ctrl+F5. В браузере создаётся отдельный демонстрационный контекст; чужие заявки недоступны. Перезагрузка сохраняет контекст через cookie, но очистка cookie или другой браузер создаёт нового посетителя.

Compose доступен только на localhost; backend и БД не публикуются наружу. Локальные demo defaults находятся в compose.yaml; собственные значения можно задать через `.env.example` → `.env`.

## Проверка интерфейса

1. Открыть модуль без ввода логина/пароля. В разделе «Продукт» выбрать цель финансирования.
2. В «Условиях» изменить сумму и срок. Проверить изменение предварительного платежа справа.
3. В «Заявке» указать синтетическую цель и финансовые показатели. Компания уже передана контекстом. При необходимости приложить PDF до 5 МБ.
4. Сохранить черновик. В «Результате» выбрать его из списка сохранённых заявок. Продолжить оформление и отправить с подтверждением.
5. Получить решение в этом же разделе: условия, объяснение оценки и история раскрываются без перехода на другие страницы. Принять либо отклонить оффер с подтверждением.
6. Перезагрузить страницу и открыть сохранённую заявку. В приватном окне убедиться, что заявки другого посетителя не видны.

Встречное предложение можно получить с выручкой 6 млн ₽, прибылью 1,2 млн ₽, долгом 0,5 млн ₽ и запросом 3 млн ₽: лимит 1,8 млн ₽. Ручное рассмотрение и отказ зависят от баллов/стоп-факторов; подробности — docs/scoring.md. Результат MANUAL_REVIEW остаётся на рассмотрении до решения банковской роли через API. Клиент может дополнить сведения после соответствующего запроса.

## Контекст и встраивание

Отсутствие экрана входа не означает общий доступ к базе. `POST /api/v1/context/` принимает существующую подтверждённую серверную сессию клиента. Для локальной демонстрации при `DEMO_VISITOR_ENABLED=1` создаёт изолированного синтетического посетителя с непригодным для входа паролем и отдельной компанией. CSRF и объектные permissions включены. Чужие заявки возвращают 404; права сотрудника посетителю не выдаются.

В реальном банковском окружении требуется адаптер проверенной идентичности основного сайта; он не реализован и не заменяется доверительными заголовками из браузера. Выключить гостевой demo fallback: `DEMO_VISITOR_ENABLED=0`. Код по умолчанию выключает его, локальный Compose включает явно.

Frontend `App` не зависит от маршрутизатора. Все четыре раздела переключаются внутри компонента; кабинет/уведомления/история не образуют дополнительных страниц. `VITE_API_BASE_URL` задаёт API-префикс при сборке, по умолчанию `/api/v1/`. Встраивание предполагает same-origin proxy и действительную проверенную backend-сессию. Детали — docs/embedded-module.md.

## Автоматические проверки

```sh
docker compose exec -T backend pytest -c pytest.ini
docker compose exec -T backend python manage.py makemigrations --check --dry-run
docker compose exec -T backend python manage.py spectacular --file /tmp/openapi.yaml --validate
node scripts/check-module.cjs
cd frontend
npm ci
npm run build
npm test
```

`check-module.cjs` проходит полный путь без login endpoint, создавая только собственную синтетическую заявку, и проверяет изоляцию второго посетителя. Другой адрес задаётся через APP_URL. `check-running.cjs` проверяет прежние login API для служебных тестов, а не пользовательский интерфейс.

## Банковская роль и исходные сценарии

Отдельный frontend сотрудника удалён по уточнению задания. REST API ручного решения, проверка роли is_staff, поиск и фильтры сохранены для банковской стороны и автоматических тестов. Для Postman доступны demo_a/demo_b/demo_c/demo_d и bank с паролем `Demo-Credit-2026!` либо DEMO_PASSWORD из окружения. Они не предлагаются как вход в клиентский интерфейс.

Сценарии seed: A — автоодобрение, B — встречная сумма, C — ручное рассмотрение, D — отказ. `docker compose exec backend python manage.py seed_demo --reset` восстанавливает только эти четыре демо-компании и удаляет их заявки/историю. Заявки новых посетителей не удаляются. Файлы на диске не очищаются.

## Разработка без Docker

Нужны Python 3.12+, Node 22+ и PostgreSQL 16+. Установить backend/requirements.lock.txt, задать DJANGO_SECRET_KEY, POSTGRES_HOST/PORT/DB/USER/PASSWORD, DEMO_PASSWORD, DEMO_VISITOR_ENABLED=1. Применить миграции, выполнить seed_demo, запустить Django на 127.0.0.1:8000. Во втором терминале: `cd frontend`, `npm ci`, `npm run dev`. Vite проксирует /api на порт 8000. SQLite — только для вспомогательных тестов.

## Документация и ограничения

- docs/embedded-module.md — границы модуля и контракт встраивания.
- docs/requirements.md и docs/pdf-compliance.md — требования пользователя и PDF кейса.
- docs/architecture.md — компоненты, ER и FSM; docs/scoring.md — скоринг и mocks.
- docs/openapi.yaml, docs/postman.json — API; docs/verification.md — фактические проверки.
- docs/product-rationale.md, docs/submission.md, THIRD_PARTY_NOTICES.

Проверки синхронные, модель правилами на Python. Нет реальных ФНС/БКИ, подписи, выдачи денег, production SSO, антивируса, HA/DR и фоновых проверок. Browser visual QA не выполнен из-за отсутствия подключённого браузера. Удалённый GitHub CI не запускался.

Перед внешним развёртыванием нужны HTTPS, собственные секреты, отключение demo fallback/seed, интеграция идентичности основного сайта и отдельный аудит безопасности. Одностраничный UI сам по себе не делает архитектуру микросервисной: backend остаётся одним модульным сервисом.

Теги hackathon-v1/v2 сохраняют прежние версии; актуальная версия определяется `git rev-parse HEAD`. GitHub-публикация ещё не выполнена.
