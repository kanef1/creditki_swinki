# Сохранённые варианты проекта

Архивы лежат в этой папке локально и не включены в Git повторно. Исходники каждой версии также доступны в истории и по неизменяемым тегам. В конце обновления создаётся полный Git bundle.

| Вариант | Исходники | Git |
|---|---|---|
| Кабинет с авторизацией и рабочим местом банка | credit-portal-v1-6c047ae.zip | snapshot-portal-v1 → 6c047ae |
| Одностраничный модуль до истории/статистики/сценариев | credit-module-v2-a11463a.zip | snapshot-module-v2 → a11463a |
| Расширенный модуль с историей, статистикой и 4 компаниями | credit-module-v3.zip | snapshot-module-v3 |
| Выбор компании на главном экране перед кредитными продуктами | credit-module-v4.zip | snapshot-module-v4 |
| Исправленные надписи UTF-8, согласованные показатели и риск в результате | credit-module-v5.zip | snapshot-module-v5 |
| Одобренный вариант до дальнейшего изменения дизайна | credit-approved-v6.zip | snapshot-approved-before-design-v6 |
| Обновлённый дизайн, контрастная типографика и карточки компаний | credit-design-v7.zip | snapshot-design-v7 |

`approved-v6-public-data.sql` сохраняет БД публичной демонстрации до правок дизайна. Предыдущий внешний вариант также доступен в `credit-public-v6.zip` по тегу `snapshot-public-v6`.

`module-v2-data.sql` — резервная копия синтетической PostgreSQL-БД до изменений этого этапа. `module-v3-data.sql` — копия после обновления. ZIP содержит исходники, lock-файлы, Docker и документацию соответствующей версии; node_modules, образы, .env, загруженные файлы и данные БД в ZIP не включены. Каталог загруженных документов сохраняется в существующем Docker volume; отдельная копия файлов документов здесь не создавалась.

`credit-history.bundle` содержит всю Git-историю и теги. `archives.json` содержит SHA-256 и версии созданных файлов. Проверка ZIP выполнена через zipfile.testzip, bundle — через git bundle verify.

`module-v5-data.sql` — дополнительная копия синтетической БД после исправления финансовых профилей и добавления риска. Отправленные ранее заявки сохраняют свои финансовые снимки; новые заявки используют уточнённые показатели.

## Как открыть старый вариант

Распаковать нужный ZIP в отдельную папку и перейти в корень исходников. Прочитать README именно этой версии. По умолчанию все варианты слушают localhost:8080, поэтому одновременно запускать их без изменения портов нельзя. Для отдельной базы используйте разные имена Compose-проектов:

```sh
# В папке исходников старого кабинета
docker compose -p credit-portal-v1 up --build -d
# После просмотра
docker compose -p credit-portal-v1 stop
```

Текущий проект перед этим можно остановить `docker compose stop` из его корня; `down -v` не используйте для переключения версий, чтобы не потерять данные. Из Git можно получить отдельный checkout через `git worktree add versions/portal-v1-source snapshot-portal-v1`.

Для восстановления SQL сначала выберите пустую изолированную БД соответствующей версии. Например, скопируйте SQL в её контейнер через `docker compose cp ... db:/tmp/restore.sql`, затем выполните `docker compose exec -T db psql -U credit -d credit -f /tmp/restore.sql`. Не импортируйте снимок поверх рабочей БД без отдельной резервной копии. Имена пользователей/БД берутся из Compose этой версии.
