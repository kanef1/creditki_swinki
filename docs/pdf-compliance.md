# Соответствие PDF кейса

Источник: «Умный кредитный кабинет предпринимателя», 16 страниц. Прочитан весь документ. Номера — страницы исходного PDF. «Реализовано» означает наличие кода; фактические проверки см. в verification.md. Исходный PDF не копируется в репозиторий.

Уточнение пользователя: самостоятельные frontend-кабинеты заменены одностраничным модулем без формы входа, четыре раздела. Банковская обработка и права сохранены на REST API, отдельный frontend сотрудника больше не входит в объём. Контекст банка в production требует адаптера; локальный visitor-контекст изолирован. Ссылки на прежние интерфейсы ниже заменены текущей компоновкой.

## Кредитный путь и критерии

Страницы 13–15 объясняют предметную область; не каждое упоминание источника данных является обязательной интеграцией. Страницы 8 и 12 содержат рекомендации и свободу выбора, а не дополнительные обязательные технологии.

| Стр. | Положение | Покрытие |
|---|---|---|
| 13 | Потребность, продукт, сумма/срок/цель, сведения о бизнесе | каталог с назначением, мастер, company + financial snapshot |
| 13 | Приём, полнота/корректность, уточнение | frontend/backend validation, submit, ADDITIONAL_INFO_REQUIRED и повторная отправка |
| 13 | Обогащение, кредитная история и регистрационные сведения | сокращённые FNS/BKI mocks; результаты по revision. Полные ЕГРЮЛ, учредители и ОКВЭД не моделируются |
| 14 | Скоринг отличается от решения; учитывается продукт | разные engine.py и модели, лимиты и ставка продукта; интеграционный тест разных продуктов |

| 15 | Результат и дальнейшие операции | объяснение, принять/отклонить, COMPLETED без денег и подписи |
| 9 | Целостность и согласованность | 4 сценария через сохранённые данные и HTTP |
| 9 | UX для клиента и банка | мастер, подсказки, причины, история; browser QA остаётся открытым |
| 9 | Enterprise-ориентированность | permissions, CSRF, Decimal, atomic/row locks, constraints, healthchecks; production HA/DR не заявлены |

## Дополнительные требования пользователя

React/TypeScript/Vite/Tailwind/shadcn, Django/DRF/PostgreSQL, десять бизнес-модулей, Python rule-based без ML/LLM, модульный монолит, четыре сценария A–D, CI, две роли и конкретный набор состояний заданы мастер-промптом. PDF не предписывает этот стек, не запрещает ML и допускает готовые компоненты. Более строгие ограничения пользователя сохранены.

Развёртывание в облаке на стр. 7 рекомендовано дополнительно. ИИ на стр. 8–12 необязателен. alfabank.ru — визуальный ориентир из мастер-промпта; PDF не требует копирования сайта или брендинга. Синтетические условия не заимствованы из реальных продуктов.
