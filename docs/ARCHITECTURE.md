# Архитектурная документация: Умный кредитный кабинет предпринимателя

## 1. Концепция и назначение системы

«Умный кредитный кабинет предпринимателя» — это цифровой кредитный конвейер полного цикла для малого и микробизнеса, разработанный в рамках кейса Альфа-Банка.

Система решает две фундаментальные задачи:
1. **Для предпринимателя (МСП / ИП):** упрощает и ускоряет доступ к кредитным ресурсам, исключая бумажную волокиту и непонятные отказы, предоставляя моментальный прозрачный расчет и трекинг статуса в реальном времени.
2. **Для банка:** автоматизирует рутинные проверки (ФНС, ЕГРЮЛ, БКИ), проводит детерминированный скоринг риска по правилам кредитной политики и предоставляет удобное автоматизированное рабочее место (АРМ) риск-андеррайтера для нестандартных кейсов.

## 3. Компоненты системы и зоны ответственности

### 3.1. Клиентский уровень (Frontend)
- **Технологии:** React 18, TypeScript, Vite, Tailwind CSS, Lucide React, Axios.
- **Интерфейс предпринимателя:**
  - Дашборд с показателями бизнеса и текущими заявками.
  - Интерактивный кредитный калькулятор с расчетом аннуитета и переплаты.
  - 4-шаговый мастер подачи заявки с автозаполнением реквизитов по ИНН.
  - Детальный экран заявки с визуальным трекером кредитного конвейера, карточкой персонального офера, понятным скоринговым отчетом и историей переходов.
- **Интерфейс риск-андеррайтера (Кабинет банка):**
  - Очередь заявок с фильтрацией по статусам и уровню риска.
  - Детальное досье заемщика с результатами проверок ФНС, ЕГРЮЛ, БКИ.
  - Модальное окно утверждения решений: стандартное одобрение, встречное предложение с коррекцией параметров, запрос дополнительных сведений, отказ со стоп-факторами.

### 3.2. Серверный уровень (Backend)
- **Технологии:** Python 3.12, Django 5.1, Django REST Framework, drf-spectacular.
- **Ключевые модули:**
  - `scoring`: Реализует детерминированный Rule-Based алгоритм расчета кредитоспособности (0-100 баллов) с классификацией уровней риска (LOW, MEDIUM, HIGH, CRITICAL).
  - `decisions`: Отделен от скоринга в соответствии с требованиями ТЗ (стр. 14). Применяет кредитную политику, формирует встречные условия при высокой долговой нагрузке и определяет маршрутизацию заявки.
  - `applications`: Управляет жизненным циклом заявки через строгий конечный автомат (FSM) с логированием каждого перехода в `StatusHistory`.

### 3.3. Уровень хранения данных (Database)
- **Технологии:** PostgreSQL 16 (с поддержкой SQLite для локальной автономной разработки).
- **Особенности:**
  - Все денежные суммы хранятся исключительно в типах `Decimal(14, 2)`.
  - Критические операции смены статуса и вынесения решений выполняются внутри `@transaction.atomic`.

## 4. Безопасность и отказоустойчивость

1. **Разграничение прав (RBAC):** Кастомные пермишены DRF (`IsEntrepreneur`, `IsBankOfficer`) проверяются на бэкенде для каждого эндпоинта.
2. **Изоляция данных:** Заемщик имеет доступ только к собственным заявкам и документам (`get_queryset` фильтрует по `applicant=request.user`).
3. **Аудит действий:** Все смены статусов и действия андеррайтеров протоколируются в `AuditLog` с фиксацией времени, инициатора и основания.
4. **Безопасность учетных записей:** Пароли хешируются с использованием PBKDF2 SHA-256. Вход по API защищен токенами авторизации.
