# Одностраничный кредитный модуль

Уточнение пользователя имеет приоритет над первоначальным заданием о самостоятельном кабинете: одна страница, без формы входа, не более четырёх разделов. Текущий frontend — компонент App с внутренним состоянием, не привязанный к React Router. Разделы: Продукт, Условия, Заявка, Результат. Данные, документы, проверки и история раскрываются внутри результата. Меню портала, самостоятельный бренд, маркетинговый hero и банковский интерфейс удалены.

Компактный заголовок и footer — демонстрационная оболочка. При встраивании их можно заменить оболочкой основного банковского сайта. API-префикс настраивается через VITE_API_BASE_URL при сборке; same-origin proxy сохраняет cookie и Host с портом. Для публикации под вложенным URL также нужно настроить base сборки Vite и соответствующий proxy основного сайта. Готовый контракт с инфраструктурой Альфа-Банка отсутствует.

Backend — один Django-сервис с модулями и PostgreSQL. Разделение сервисов по доменным/эксплуатационным границам и интеграция с корпоративной платформой — отдельная задача. Количество страниц frontend не определяет число микросервисов.

## Идентичность без экрана входа

POST context/ проходит CSRF и сначала принимает уже подтверждённую сервером клиентскую сессию. Если её нет, только при явно включённом DEMO_VISITOR_ENABLED создаётся отдельный синтетический пользователь с unusable password и четырьмя собственными демо-компаниями. У каждой компании разные финансовые данные и начальная заявка, обработанная обычным серверным конвейером. Роль сотрудника не выдаётся. Данные изолированы membership и queryset. Повторный запрос с существующей клиентской сессией не создаёт нового пользователя и не дублирует начальные заявки. Локальный Compose включает demo fallback; настройки Django по умолчанию выключают его. Создание контекста ограничено throttle.

Сценарии для жюри раскрываются внутри «Продукта», выбор компании по демо-ИНН находится на главном экране перед кредитными продуктами. Статистика, список заявок и история всех версий офферов находятся в «Результате», с серверной фильтрацией и пагинацией. Дополнительных разделов верхнего уровня нет. Метрики считаются по доступным пользователю заявкам, сумма офферов не выдаётся за реальный объём кредитных выдач. Параметры и порядок демонстрации описаны в jury-scenarios.md.

Реальная интеграция должна получать подтверждённую идентичность от системы основного сайта (например, после серверной проверки токена/сессии по согласованному контракту). Адаптер SSO не реализован. Произвольные user_id/role из браузерных заголовков не считаются авторизацией. Production нельзя запускать с публичным анонимным доступом к общей компании.

Банковские решения по-прежнему требуют отдельной роли на REST API. Публичного переключателя «Стать сотрудником банка» нет. Потребительский модуль не показывает интерфейс андеррайтера. Запросы сведений и ручные решения видны клиенту через актуальный статус и причину.

## Компоновка и кнопки

Ритм отступов: 10–12 px между label и полем, 25 px между полями, 26 px между содержимым и действиями, 29 px перед действиями в диалоге. Главная кнопка красная; вторичная с серой заливкой без контрастной рамки; третичное действие текстовое. Выбор продукта отмечен тонкой красной линией. CSS-классы button-primary/button-secondary/button-ghost не конфликтуют с утилитой Tailwind outline. Видимый фокус клавиатуры сохранён отдельно через focus-visible.

В референсе kanef1.online по прямому HTTP доступны компактная форма и результаты в одном frontend. Исходный код, банковские иллюстрации, SMS-симуляция и универсальные коды не копировались. Визуальный просмотр референса и нового интерфейса в браузере не выполнен: список подключённых браузеров пуст. Нет заявления о пиксельном соответствии.
