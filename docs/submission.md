# Подготовка к сдаче

Страница 7 требует GitHub-репозиторий с историей и идентификатором версии к дедлайну. Локальный Git и тег не заменяют GitHub-публикацию. Удалённый репозиторий не выбран пользователем; код не отправлялся, доступ никому не предоставлялся.

1. Выполнить `docker compose up --build -d --wait` с работающим Docker Linux engine. Проверить приложение, `/health/`, `/api/docs/`.
2. Пройти README-сценарий с новой заявкой через мастер, четырьмя результатами и ручным запросом сведений. Проверить desktop/mobile в браузере.
3. Выполнить тесты и сохранить логи: `docker compose exec backend pytest -c pytest.ini`, frontend build/test.
4. Выбрать GitHub-репозиторий, проверить отсутствие секретов и личных данных, сохранить историю. Для private repo предоставить доступ аккаунту жюри `alfa-hack-2026`, указанному в кейсе.
5. После всех последующих изменений создать новый тег, например `hackathon-v3`, и указать `git rev-parse HEAD` в форме сдачи. Тег v1 относится к первоначальной версии, v2 — к сверке PDF. Не перемещать старые теги. Дедлайн в PDF не указан: дату нужно взять из правил мероприятия.
6. Сдать README, THIRD_PARTY_NOTICES, архитектуру/ER/FSM, описание скоринга, обе матрицы требований, продуктовые гипотезы, OpenAPI, Postman и verification.md. Исходный PDF не копируется в репозиторий.

Облачное развёртывание рекомендовано дополнительно. Перед внешней публикацией нужны HTTPS и замена локальных demo defaults; текущая Compose-конфигурация доступна только на localhost.
